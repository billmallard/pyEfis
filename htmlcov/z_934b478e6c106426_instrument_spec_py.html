17"""Declarative instrument definitions -- the single source of truth for the 

18pyEfis instrument catalog. 

19 

20One :class:`InstrumentSpec` record per instrument type is the contract that the 

21three "mirrors" derive from, so they can no longer drift apart: 

22 

23 1. the screen-builder factory (constructs the widget, applies options), 

24 2. the editor schema exporter (:mod:`pyefis.editor.schema` -> ``schema.json``), 

25 3. the web configurator's instrument "twin" (renders the live preview). 

26 

27An instrument has THREE distinct kinds of input; keeping them separate is the 

28whole point of this module (see ``docs/instrument_spec.md``): 

29 

30 1. Config properties (:attr:`InstrumentSpec.properties`, list of :class:`Prop`) 

31 Layout / appearance / feature options the panel designer sets in the 

32 editor. Written into the screen YAML and applied to the widget. 

33 e.g. ``aircraft_symbol``, ``show_tas``, ``startAngle``, ``decimal_places``. 

34 

35 2. FIX-database values (:attr:`InstrumentSpec.fix_values`, list of 

36 :class:`FixValue`) 

37 Runtime values the instrument reads from fix-gateway (the FIX item's 

38 ``min`` / ``max`` / ``aux``), NOT set in the panel editor. 

39 e.g. V-speeds (Vne...), gauge warn/alarm bands, range. Described here so a 

40 future FIX-database editor can drive them; the panel editor only reads 

41 them (as preview). 

42 

43 3. Preview hints (:attr:`InstrumentSpec.preview`, dict) 

44 Representative sample data so the configurator twin can draw a realistic 

45 instrument with no live FIX connection. Never written to a device. 

46 

47This module is intentionally **Qt-free** so the catalog can be validated and 

48the schema exported in CI without a display or the GL stack. The Qt-dependent 

49builder callable is bound onto the record in ``screenbuilder_factory.py``. 

50"""

81 """Marks a :class:`Prop` as *live-bindable*: the setting can also be driven at
