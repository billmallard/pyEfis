17"""tab_section -- an in-screen container instrument (pyEfis#131 / AER-172). 

18 

19Occupies one section of a screen, like any other instrument, and lets the 

20pilot/config switch between named tab-views inside that section, each holding 

21its own real instruments. Distinct from the whole-screen switching in 

22gui.Main.showScreen (pyEfis#72) -- that swaps entire authored screens; this is 

23one container among many instruments on a single screen. 

24 

25v1 scope (see pyEfis#131 "Open questions -- RESOLVED"): 

26 * touch/click tab bar only -- no hardware-button switching yet; 

27 * reload/power-up always lands on the configured ``default_tab``, not the 

28 last-selected tab (no runtime persistence); 

29 * a tab_section cannot be nested inside another tab_section. 

30 

31Encoder: each tab page inherits the enclosing screen's ``encoder`` / 

32``encoder_button`` / ``encoder_outer`` / ``encoder_timeout`` keys, so an 

33``encoder_order`` instrument inside a tab is driven by the screen's knob. Without this a page 

34config carried only ``layout`` + ``instruments``, the page's encoder keys were 

35None, and its controller silently never connected (AER-810). Every page 

36connects to the same keys, but ``EncoderController`` ignores input while its 

37page is not visible, so only the shown tab responds. 

38 

39Each tab's nested ``instruments:`` list is built through the exact same 

40``Screen`` (screenbuilder.py) that a top-level screen uses -- the tab content 

41widget below *is* a ``Screen`` instance, constructed from an explicit config 

42dict (``layout`` + ``instruments``, the same two keys a screen's own YAML 

43carries) rather than looked up by name via gui.Main. This reuses grid layout, 

44create_instrument() dispatch, and option application unchanged; there is 

45nothing tab_section-specific about how a tab's contents get built or resized. 

46"""

221 def _layout_pages(self): 

222 """Position the tab bar + content area against THIS widget's own 

223 box, on whichever edge ``tab_position`` names, then size every page 

224 (current tab or not) to that content area -- the coordinate-space 

225 recursion pyEfis#131 calls out as the real lift: a tab's instruments 

226 are laid out against the container's box, never the enclosing 

227 screen's. 

228 

229 West/East bars are sized off ``sizeHint().width()`` -- rotating the 

230 bar to a side shape rotates the tab labels too, but Qt keeps 

231 reporting the bar's "thickness" (the dimension we need to reserve) 

232 on the width axis of its sizeHint, not the height.""" 

233 tab_position = self.tab_position if self.tab_position in _TAB_BAR_SHAPE \ 

234 else "top" 

235 self.tab_bar.setShape(_TAB_BAR_SHAPE[tab_position]) 

236 if tab_position in ("top", "bottom"): 

237 bar_size = self.tab_bar.sizeHint().height() 

238 content_w = self.width() 

239 content_h = max(0, self.height() - bar_size) 

240 if tab_position == "top": 

241 bar_geom = (0, 0, self.width(), bar_size) 

242 stack_geom = (0, bar_size, content_w, content_h) 

243 else: 

244 bar_geom = (0, content_h, self.width(), bar_size) 

245 stack_geom = (0, 0, content_w, content_h) 

246 else: 

247 bar_size = self.tab_bar.sizeHint().width() 

248 content_w = max(0, self.width() - bar_size) 

249 content_h = self.height() 

250 if tab_position == "left": 

251 bar_geom = (0, 0, bar_size, self.height()) 

252 stack_geom = (bar_size, 0, content_w, content_h) 

253 else: 

254 bar_geom = (content_w, 0, bar_size, self.height()) 

255 stack_geom = (0, 0, content_w, content_h) 

256 self.tab_bar.setGeometry(*bar_geom) 

257 self.stack.setGeometry(*stack_geom) 

258 for page in self._pages: 

259 page.setGeometry(0, 0, content_w, content_h)
